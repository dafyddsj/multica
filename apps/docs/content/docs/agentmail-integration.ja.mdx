[AgentMail](https://www.agentmail.to) はプログラム可能な受信箱を提供します。Multica ではワークスペースが一度接続し、各エージェントにアドレスを付与します。ブランド名 **AgentMail** は英語のままです。

<Callout type="info">
これは[通知 Inbox](/inbox) ではありません。設定 → **メール** とエージェントの **メール** タブがメールボックスです。`/{slug}/inbox` はこれまで通り、割り当て・メンション・失敗通知です。
</Callout>

メール本体は AgentMail にあります。Multica が保存するのは接続と受信箱のメタデータ、および密封したキーだけです。本文は保存しません。

## できること

- ワークスペース単位の接続：**hosted**（プロセス環境の組織キー）または **bring your own**（組織キーまたは pod スコープキー）。
- エージェントページの **メール** タブ。新規アドレス（ユーザー名 + AgentMail アカウントのドメイン、カスタムドメインを含む）を作るか、アカウント上の既存の受信箱をリンクできます。
- オフにするときは受信箱を残すか削除するかを選びます。削除は再確認が必要です。
- [タスク](/tasks)のクレーム時に、その受信箱だけに狭い MCP を注入します。読み取り・送信・下書きはできます。受信箱、pod、ドメイン、API キーの作成や削除はできません。
- エージェント所有者とワークスペースの owner/admin は、メールタブでテキストのみの閲覧ができます（受信トレイ、送信済み、下書き、予約送信、すべてのメール、ゴミ箱、追加フォルダ）。

メンバーは設定 → メールで付与済みアドレスを見られます。エージェントのメールタブや閲覧はできません。

## サーバー側の前提

キーを密封できるまで、メールタブは表示されません。

```sh
openssl rand -base64 32
```

```sh
MULTICA_AGENTMAIL_SECRET_KEY=<base64 32-byte key>
```

hosted 接続には、プロセス環境の AgentMail 組織キーも必要です（データベースには書きません）。

```sh
MULTICA_AGENTMAIL_ORG_KEY=am_...
```

`AGENTMAIL_ORG_API_KEY` も受け付けます。EU では `MULTICA_AGENTMAIL_API_BASE` を `https://api.agentmail.eu/v0` にできます。

hosted の組織キーが無い場合でも、**設定 → メール** で bring your own が使えます。組織キーまたは pod スコープキーを貼り付けます。inbox スコープのキーは拒否されます。

hosted ワークスペースの進行中受信箱はデフォルトで 5 件までです（`provisioning`、`minting_key`、`active`、`disabling`）。

## ワークスペースを接続する

1. **設定 → メール** を開きます。
2. **Hosted**（サーバーが提供している場合）または **Bring your own** を選びます。
3. 接続します。hosted と bring your own の切り替えは、先に切断が必要です。

切断すると全エージェントの受信箱を取り消し、hosted の場合はワークスペースの pod も削除します。

## エージェントに受信箱を付与する

1. エージェント → **メール** を開きます。
2. **新規作成** または **既存をリンク** を選びます。
3. 新規作成：ユーザー名とドメイン（`agentmail.to` または AgentMail アカウントのカスタムドメイン）を選びます。既存をリンク：アカウント上の未使用の受信箱を選びます。
4. Multica が狭いキーを密封します。アドレスはスイッチの下と、ワークスペースのメール一覧に出ます。メールタブはメールボックスになります。

オフにするときは **受信箱を残す** か **受信箱を削除** を選びます。残すとエージェントの接続だけ切れ、受信箱は AgentMail アカウントに残るので後から再リンクできます。削除は再確認のあと、遠隔の受信箱とそのメールを消します。新規作成をやり直すと、同じ `client_id`（エージェント UUID）を再利用します。

アーカイブしても受信箱は取り消しません。復元後もアドレスは残ります。

## エージェントがメールを使う方法

inbox キーはエージェント行にも `custom_env` にも保存しません。クレーム時の MCP 設定 `mcpServers.agentmail` にだけマージされ、そのクレームと一緒に捨てられます。ここでの失敗はクレーム自体を失敗させません。

メールタブの閲覧は同じキーでスレッドをその場で取得し、プレーンテキストだけを返します。AgentMail の HTML は捨てられ、描画されません。
