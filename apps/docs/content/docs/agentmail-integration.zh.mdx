[AgentMail](https://www.agentmail.to) 提供可编程邮箱。在 Multica 里，工作区先连接一次，再给每个智能体开通自己的地址。品牌名 **AgentMail** 保持英文。

<Callout type="info">
这不是[站内收件箱](/inbox)。设置 → **邮箱** 和智能体 **邮箱** 页才是电子邮件。`/{slug}/inbox` 仍然是指派、提及和失败通知。
</Callout>

邮件本身留在 AgentMail。Multica 只存连接和邮箱元数据，以及加密后的密钥，不存正文。

## 你能得到什么

- 工作区级连接：**托管**（进程环境里的组织密钥）或 **自带密钥**（你的组织级或 pod 级密钥）。
- 智能体页上的 **邮箱** 页。可以新建地址（用户名 + AgentMail 账号上的域名，含自定义域名），或关联账号里已有的邮箱。
- 关闭邮箱时选择保留远端邮箱，或删除它。删除需要二次确认。
- [任务](/tasks)被领取时，Multica 注入只覆盖这一只邮箱的 MCP。智能体可以读、发、写草稿，不能创建或删除邮箱、pod、域名或 API 密钥。
- 智能体所有者以及工作区 owner/admin 可以在邮箱页查看纯文本邮件（收件箱、已发送、草稿、定时、所有邮件、垃圾箱，以及额外文件夹）。

成员可以在设置 → 邮箱看到已开通的地址，但不能打开智能体邮箱页或阅读邮件。

## 服务端前置

在服务器能封存密钥之前，邮箱页不会出现：

```sh
openssl rand -base64 32
```

```sh
MULTICA_AGENTMAIL_SECRET_KEY=<base64 32-byte key>
```

托管连接还需要进程环境里的 AgentMail 组织密钥（不会写入数据库）：

```sh
MULTICA_AGENTMAIL_ORG_KEY=am_...
```

也接受 `AGENTMAIL_ORG_API_KEY`。欧盟部署可以把 `MULTICA_AGENTMAIL_API_BASE` 设为 `https://api.agentmail.eu/v0`。

没有托管组织密钥时，**设置 → 邮箱** 仍可自带密钥：粘贴组织级或 pod 级密钥。只覆盖单只邮箱的密钥会被拒绝。

托管工作区默认最多 5 个进行中的邮箱（`provisioning`、`minting_key`、`active`、`disabling`）。

## 连接工作区

1. 打开 **设置 → 邮箱**。
2. 选择 **托管**（如果服务器提供）或 **自带密钥**。
3. 连接。托管和自带密钥之间切换必须先断开。

断开连接会撤销所有智能体邮箱；托管模式下还会删除该工作区的 pod。

## 给智能体开通邮箱

1. 打开智能体 → **邮箱**。
2. 选择 **新建** 或 **关联已有**。
3. 新建：选择用户名和域名（`agentmail.to` 或 AgentMail 账号上的自定义域名）。关联已有：选择账号里尚未被占用的邮箱。
4. Multica 封存一把收窄后的密钥。地址出现在开关下方，以及工作区邮箱名单里。邮箱页随后成为邮箱界面。

关闭时选择 **保留邮箱** 或 **删除邮箱**。保留会断开智能体，远端邮箱留在 AgentMail 账号上，之后可以再关联。删除需要二次确认，随后删除远端邮箱及其邮件。再次新建会复用同一个 `client_id`（智能体 UUID）。

归档智能体不会撤销邮箱。恢复后地址仍在。

## 智能体怎么用邮件

邮箱密钥不写在智能体行上，也不进 `custom_env`。它只在领取任务时合并进 MCP 配置 `mcpServers.agentmail`，并随这次领取结束。这里失败不会让领取失败。

邮箱页的阅读器用同一把密钥现场拉取会话，只返回纯文本。AgentMail 返回的 HTML 会被丢掉，不会渲染。
