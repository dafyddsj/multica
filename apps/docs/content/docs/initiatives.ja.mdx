イニシアチブは[プロジェクト](/projects)の長期的な親です。ワークスペース内の階層は ワークスペース → イニシアチブ → プロジェクト → イシュー です。

プロダクト、サービス、プログラムはイニシアチブに置きます。プロジェクトはその親の中の期限付きの作業です。スプリント、移行、リリースが該当します。1 つのプロジェクトが属せるイニシアチブは最大 1 つです。イシューはプロジェクト経由でのみ紐づきます。イシューからイニシアチブへの直接のリンクはありません。

プロジェクトが 1 つだけの作業にイニシアチブは不要です。複数のプロジェクトが同じプロダクトやプログラムを共有し、個別のプロジェクトが終わったあともそれを残しておきたいときに作成します。

## イニシアチブの構成

| 内容 | 役割 |
|---|---|
| **名前、アイコン、説明** | このイニシアチブが表すプロダクトまたはプログラム。 |
| **ステータス** | `planned`、`in_progress`、`paused`、`completed`、`cancelled`。プロジェクトと同じ語彙です。 |
| **優先度** | `urgent`、`high`、`medium`、`low`、`none`。 |
| **リード（lead）** | メンバーまたはエージェント。イニシアチブの調整役を示します。 |
| **開始日と目標日** | 任意のカレンダー期間。 |
| **プロジェクト** | このイニシアチブの下にある期限付きの作業。 |

## イニシアチブとプロジェクトの関係

1 つのプロジェクトが属せるイニシアチブは最大 1 つです。作成時に紐づけることも、あとから紐づけることもできます。

```bash
multica project create --title "2026 Week 16 Sprint" --initiative <initiative-id>
multica project update <project-id> --initiative <initiative-id>
multica project update <project-id> --initiative ""
```

`--initiative ""` はプロジェクトをイニシアチブから外します。イシューはプロジェクトに残ります。イニシアチブの紐づけを変えてもイシューは動きません。

イニシアチブのステータスとプロジェクトのステータスは互いに独立しています。子プロジェクトがすべて完了してもイニシアチブは自動的に `completed` にならず、イニシアチブのステータスを変更しても中のプロジェクトが一括変更されることはありません。

## イニシアチブリード

リードはメンバーまたはエージェントで、イニシアチブの調整役を示します。権限設定ではありません。

## 作成、編集、削除

イニシアチブの作成と編集はワークスペースのメンバーなら誰でもできます。削除できるのは `owner` と `admin` だけです。

```bash
multica initiative list
multica initiative get <initiative-id>
multica initiative create --title "Platform"
multica initiative update <initiative-id> --status in_progress
multica initiative delete <initiative-id>
```

<Callout type="warning">
イニシアチブを削除しても中のプロジェクトは削除されません。プロジェクトは紐づけが解除され、ワークスペースにそのまま残ります。イニシアチブの説明とステータスは完全に削除されます。
</Callout>
